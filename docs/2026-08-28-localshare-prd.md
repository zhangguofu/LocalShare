## 1. 问题定义

### 1.1 一句话问题

同一局域网内的多台异构桌面系统（Windows / macOS）之间，缺少一种"**快速、直接、无需公网中转、无需账号**"的文件与文件夹互传方式。

### 1.2 现有手段的痛点

| 手段 | 痛点 |
|------|------|
| U 盘 / 移动硬盘 | 需要物理接触；反复插拔 |
| 网盘 / IM 软件 | 走公网中转：速度受限于上行带宽与服务器，文件需先上传再下载；依赖账号；隐私顾虑 |
| 公网传输服务（如临时文件站） | 同样依赖公网；文件滞留第三方服务器；大文件受限 |
| 操作系统自带共享（SMB / AirDrop） | AirDrop 仅苹果生态互通；SMB 在异构系统间配置繁琐（权限、工作组、凭据），对普通用户不友好 |

### 1.3 本工具的定义

一个运行在 Windows / macOS 上的桌面应用：同一局域网内两台设备运行本应用即可**互相发现**并**直接互传文件与文件夹**（对等模式，无中心服务器），保持目录结构完整。

## 2. 目标与非目标

### 2.1 目标（MVP）

- G1：Windows 与 macOS 双平台，同一应用对等互传。
- G2：局域网内自动发现在线设备；发现失效时可用"手动输入 IP 直连"兜底。
- G3：文件与文件夹拖拽发送；文件夹逐文件流式传输，保持目录结构（含空目录、中文文件名、零字节文件）。
- G4：接收方确认机制：显示发送者、内容、大小，接受后才开始传输。
- G5：接收时同名冲突由用户决策（覆盖 / 选择其他位置 / 拒绝）。
- G6：传输进度实时可见；中断自动清理临时文件，不产生半成品。
- G7：全程局域网直连，不依赖公网、无需账号。

### 2.2 非目标（MVP 明确不做，记录在案）

- 断点续传（传输中断需重传）
- 文本 / 剪贴板 / 聊天消息传输
- 端到端加密与完整性哈希校验（局域网可信前提，明文传输）
- 传输历史持久化（仅会话内展示）
- 目录"镜像删除"（覆盖时不删除旧目录中本次未涉及的文件）
- 多传输并发、限速
- 组播 / 跨 VLAN 发现、移动端

## 3. 目标用户与使用场景

### 3.1 目标用户

- **个人多设备用户**：同时使用 Windows 台式机与 MacBook 的开发者、设计师、内容创作者。
- **小团队**：局域网内共享素材、交付物，不依赖公司网盘或公网。
- 特征：对"快"和"直接"敏感；不希望为一次传输注册账号、上传公网；对局域网安全风险可接受（可信环境）。

### 3.2 典型场景（用户故事）

**US-1（日常互传）**：作为双系统用户，我在 Windows 上写好文档/代码包，想立刻在 MacBook 上查看——打开两个应用，MacBook 在设备列表看到 Windows 机器，拖拽文件夹过去，接收方点"接受"，目录结构原样到达。

**US-2（大文件）**：作为视频创作者，我要把 1GB 的成片从 Mac 传到 Windows 剪辑机。局域网千兆带宽下直接点对点传输，不经过网盘二次上下行。

**US-3（同目录反复同步）**：我多次把 `work/` 目录从一台机器同步到另一台，目标位置已有旧版本——确认框提示冲突，我选择"接受并覆盖"，同名文件被替换，旧目录里本次未涉及的文件不受影响。

**US-4（发现失效的兜底）**：两台设备被无线 AP 隔离（广播不通），我在设备列表下方手动输入 `192.168.1.23:45556` 直连，传输照常。

**US-5（后台接收）**：我关掉了窗口，MacBook 仍在 Dock 驻留接收。同事从 Windows 发来文件，我收到系统通知，点击直达保存目录。

## 4. 功能需求

| FR-9 | 传输实时进度：显示百分比与已传/总字节（当前文件 + 总体） | Must | 已实现 |

| 编号 | 需求 | 优先级 | 状态 |

## 5. 非功能需求

| 编号 | 类别 | 需求 |
|------|------|------|
| NFR-1 | 平台 | Windows 10+ 与 macOS 12+（Electron 双平台安装包：macOS arm64/x64，Windows x64） |
| NFR-2 | 性能 | 千兆局域网 1GB 文件传输可用，CPU 占用合理；传输全程内存占用恒定（流式，不整文件载入） |
| NFR-3 | 发现时效 | 设备在线/离线在 12 秒内反映到列表 |
| NFR-4 | 安全 | 局域网可信前提、明文传输；接收方确认是唯一授权机制；接收端路径清洗，拒绝 `..`、绝对路径、Windows 保留字符与保留名（防路径穿越） |
| NFR-5 | 可靠性 | 原子落盘（`.part` → rename）；任何中断不留半成品；所有失败路径有清晰提示 |
| NFR-6 | 可维护性 | 网络层从零自研（仅 Node 内置 `dgram`/`net`），协议可控可审计；UI 层用成熟方案（Electron + Vue3 + Element Plus）；单进程架构 |
| NFR-7 | 可测试性 | 协议/路径清洗/存储/目录树可纯单元测试；传输与发现在 `127.0.0.1` 回环集成测试，CI 可跑 |
| NFR-8 | 安装体验 | 国内镜像固化进仓库（`.npmrc`），依赖安装开箱即用；安装包未签名，附"未知开发者"绕过说明 |
| NFR-9 | 隐私 | 无账号、无遥测、无公网流量；传输数据仅经局域网 |

## 6. 功能拆解

### 6.1 功能树（Epic → Feature → 功能点）

```
局域网文件分享
├── E1 设备发现
│   ├── F1.1 在线设备列表（自动发现 / 手动直连）      → FR-1, FR-2, FR-3
│   ├── F1.2 心跳与离线剔除（12s 超时）              → FR-1
│   ├── F1.3 端口策略（严格端口，被占报错退出）        → FR-4
│   └── F1.4 发现通道配置（UDP 端口，重启生效）       → FR-22, FR-27
├── E2 传输
│   ├── F2.1 发送（拖拽/选择、目录树遍历、逐文件流式）  → FR-5, FR-6, FR-7, FR-8
│   ├── F2.2 接收（确认、落盘、进度）                 → FR-9, FR-10, FR-11, FR-12
│   ├── F2.3 冲突处理（覆盖/换位置/拒绝）             → FR-13, FR-14, FR-15, FR-26
│   ├── F2.4 取消与中断（双方取消、断线清理、超时）     → FR-16 ~ FR-21
│   └── F2.5 传输队列（会话内列表，不持久化）          → FR-25
├── E3 系统集成
│   ├── F3.1 后台驻留（关窗继续接收、托盘/Dock）       → FR-23
│   ├── F3.2 系统通知（完成通知、点击直达目录）         → FR-24
│   └── F3.3 设置页（设备名/保存目录/端口）            → FR-22
└── E4 安全与健壮性
    ├── F4.1 接收确认授权模型                        → FR-11, NFR-4
    ├── F4.2 路径清洗（穿越/非法字符/保留名）           → NFR-4, FR-21
    └── F4.3 连接健壮性（首帧校验/超时/文件数核对）     → FR-28 ~ FR-31
```

集成测试（`discovery.test.ts` / `transfer.test.ts` 共 13 个）使用真实 UDP/TCP 绑定回环地址。**在禁止网络绑定的沙箱环境中必然失败**（`bind EPERM`），这是环境限制而非代码缺陷；请在允许网络绑定的普通终端（本机 shell 或 CI）中运行 `npm test` 验证。单元测试（40 个）不依赖网络，任何环境均可运行。
